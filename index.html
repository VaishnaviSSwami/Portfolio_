Short plain-language explainers on things I use every day. Tap one to open it.

What does a data quality check actually check?
Data quality · 2 min read

Think of it as a checklist run on data before anyone uses it. Is anything empty that should not be (null check)? Do the columns match what we expect (schema check)? Is every row unique where it should be (primary-key check)? Do the numbers match the source system (reconciliation)?

If a check fails, the pipeline should stop or raise an alert instead of passing bad data to a report.

Why Airflow? A simple view of scheduling pipelines
Orchestration · 2 min read

A pipeline usually has many steps, and some must finish before others start. Airflow lets you write those steps as a DAG, a graph of tasks with a clear order, and runs them on a schedule.

It also retries failed tasks, shows what failed and when, and makes it easy to rerun only the part that broke.

Incremental processing: don’t reload everything every day
Spark and data lakes · 2 min read

If a table has years of history, reloading all of it daily wastes time. Incremental processing only handles the new or changed rows since the last run.

Partitioning the data, for example by date, helps Spark read only the partitions it needs.
